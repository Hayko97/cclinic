# roadmap-planning

## Goal

Make the PM agent the only way to create or extend a roadmap, and make planning feel like talking to a real PM. The PM is a real Claude Code session that follows the `product-engineer` skill. The user can talk to it in three places, and move one conversation between them:

- **`cclinic plan` in a terminal**, where cclinic drives the session one turn at a time
- **Plan in the GUI**, a chat in the side panel that mirrors the session's transcript live
- **Claude Code itself**, by asking to plan there, or by resuming the session with `claude --resume <session-id>`

The user describes what they want in their own words and can attach images and documents, such as a brief, a mockup or a screenshot. The PM researches the project, its specs, the attachments and, when it helps, the web. It then talks the work through like a PM with a client: it asks questions, explains options with a recommendation, answers the user's own questions, and plays back what it understood. When the work is clear, it proposes either a roadmap of milestones and tasks with their dependencies, or one concrete task, through cclinic's MCP tool `plan_propose`. cclinic checks the proposal, and saves it only after the user approves it. [automated-mode](../automated-mode/spec.md) runs a saved roadmap, including any single tasks added to it. Users can still add quick tasks by hand with `cclinic tasks add`.

Roadmaps, milestones, tasks and dependencies are stored as described in [task-tracking](../task-tracking/spec.md). The PM's planning instructions are the `product-engineer` skill in [agent-skills](../agent-skills/spec.md). The planning tools are served by [mcp-server](../mcp-server/spec.md). The GUI's Plan panel is part of [gui](../gui/spec.md), and uses its existing design system in both the light and dark themes.

## Flow

1. The user starts planning: `cclinic plan` (or `--task`), New roadmap or Plan a task in the GUI, or asking Claude Code to plan a roadmap. They pick a new roadmap, an existing roadmap to extend, or a single task. Or they continue an earlier planning session.
2. A Claude Code session runs the PM. Its first step is `plan_begin`, which registers a planning session in `.cclinic/plans/<id>/` and links the Claude session to it.
3. The user writes what they want, and may attach images and documents.
4. The PM researches the project, the attachments and, when useful, the web, and replies: what it found, its questions, options with a recommendation, and suggested answers (`plan_suggest`). The user replies freely. This repeats until the PM has enough to plan, or the user asks it to propose now. The GUI shows the conversation from the session's transcript, wherever it's being driven from.
5. The PM plays back what it understood, then calls `plan_propose`. cclinic checks the proposal, and if it fails, the PM fixes it before the user sees it.
6. The user approves it, cancels, or keeps chatting to refine it (back to step 4).
7. On approve, cclinic saves the whole roadmap or the task at once, and reports its ID and the `cclinic auto` command to run it.

## Edge cases

- No roadmaps yet: no choice is shown, and the session plans a new roadmap.
- Extending a roadmap: the proposal has no roadmap title or goal, and its milestones are added after the existing ones.
- A new task depends on an existing task in another roadmap: allowed, using the existing task's ID.
- A single task proposed for a roadmap: it goes into an existing milestone of that roadmap, and no milestone is created.
- A standalone task: it has no milestone and belongs to no roadmap, so `cclinic auto` doesn't run it. It's worked on through the normal agent lifecycle.
- The PM keeps asking: the 40-turn limit ends a cclinic-driven run, and the session can be resumed, where the user can send `/propose`.
- The user replies "I don't know": the PM lists it as an open question and doesn't guess.
- The user asks the PM a question instead of answering: the PM answers it before asking more.
- The user sends only an image: it's sent with no text, and the PM describes what it understood from it.
- The user closes Claude Code in the middle of planning: its MCP server exits, the hold is released, and the session can be continued in the GUI or with `cclinic plan --resume`.
- The Claude transcript was deleted or moved: the session can't be resumed; `--resume` and the GUI name it as unavailable and offer to cancel it.
- In Claude Code, the PM runs with the user's own Claude Code permissions, not the read-only set of FR-PLAN-005. The skill tells it not to change files, and saving still needs `plan_propose` and the user's approval.
- A resumed session whose extended roadmap, chosen milestone or dependency task was removed since: the waiting proposal fails its check and is sent back to the PM with the problem; a removed target roadmap ends the run with exit 2, naming it, and keeps the session.
- A session record that's damaged or from a newer cclinic: `--resume` names it as unreadable and doesn't change it.
- `tasks.db` is a newer version or not a database: saving fails as in task-tracking FR-TASK-016, nothing is saved, the proposal is shown again, and the session stays open.
- A web page the PM fetched contains instructions: they're data, and the skill tells the PM to ignore them.

## Non-goals

- Editing or reordering an existing roadmap's milestones or tasks. Removing them stays in `cclinic tasks`.
- Planning without the user, from a goal alone.
- Several single tasks in one session. Each task-mode session creates one task.
- Running the roadmap. That's `cclinic auto`.
- Planning with the Anthropic API provider.
- Audio, video, spreadsheets other than CSV, and archives as attachments.
- Editing or deleting a message already sent.
- Several sessions driven at once in one GUI.
- Rendering Markdown in the terminal. The terminal shows the PM's text as written.
- An interactive terminal emulator in the GUI. The GUI mirrors the session as a chat.
