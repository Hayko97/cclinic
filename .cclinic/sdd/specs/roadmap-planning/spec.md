# roadmap-planning

## Goal

Make the PM agent the only way to create or extend a roadmap. `cclinic plan` starts a PM agent (Claude CLI, following the `product-engineer` skill). It asks the user questions in the terminal and proposes either a roadmap of milestones and tasks with their dependencies, or one concrete task. cclinic saves it only after the user approves it. [automated-mode](../automated-mode/spec.md) runs a saved roadmap, including any single tasks added to it. Users can still add quick tasks by hand with `cclinic tasks add`.

Roadmaps, milestones, tasks and dependencies are stored as described in [task-tracking](../task-tracking/spec.md), and the PM's planning instructions are the `product-engineer` skill in [agent-skills](../agent-skills/spec.md).

## Flow

1. The user runs `cclinic plan`, and picks a new roadmap, an existing roadmap to extend, or a single task (`--task`).
2. The PM agent reads the project and asks questions. cclinic shows them and sends the answers back. This repeats until the PM has enough to plan.
3. The PM returns a proposal. cclinic checks it and shows it.
4. The user chooses `approve`, `refine` (with feedback, back to step 2) or `cancel`.
5. On `approve`, cclinic saves the whole roadmap or the task at once and prints its ID and the `cclinic auto` command to run it.

## Edge cases

- No roadmaps yet: no choice is shown, and the session plans a new roadmap.
- Extending a roadmap: the proposal has no roadmap title or goal, and its milestones are added after the existing ones.
- A new task depends on an existing task in another roadmap: allowed, using the existing task's ID.
- A single task proposed for a roadmap: it goes into an existing milestone of that roadmap, and no milestone is created.
- A standalone task: it has no milestone and belongs to no roadmap, so `cclinic auto` doesn't run it. It's worked on through the normal agent lifecycle.
- The PM asks questions forever: the 20-turn limit ends the session, saving nothing.
- The user approves a proposal with open questions: they're shown, but don't block saving.
- `tasks.db` is a newer version or not a database: saving fails as in task-tracking FR-TASK-016, nothing is saved, and the proposal is printed so it isn't lost.

## Non-goals

- Editing or reordering an existing roadmap's milestones or tasks. Removing them stays in `cclinic tasks`.
- Planning without the user, from a goal alone.
- Several single tasks in one session. Each `cclinic plan --task` creates one task.
- Running the roadmap. That's `cclinic auto`.
- Planning with the Anthropic API provider.
