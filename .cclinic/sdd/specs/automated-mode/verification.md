# automated-mode: verification

Test cases for automation testers. Start each automated test's name with its `TC` ID.

## Test setup

- Test runner: Vitest, with unit tests colocated in `src/core`, and integration and e2e tests in `test/integration` and `test/e2e`.
- Each test uses a fresh temporary Git repository with one commit, the cclinic skills installed, and a `tasks.db` built through the task store's plan save (as `cclinic plan` would save it), with roadmap 1 holding the test's milestones and tasks. Commands below include `--roadmap 1` unless they say otherwise.
- No test calls real Claude. Tests put a fake `claude` on `PATH` (extending `test/fixtures/fake-claude/claude`) that tells the roles apart by prompt, writes chosen files into its working folder, and returns scripted verdicts (`approve`, `refine`, `pass`, `fail`, `changes`, invalid JSON), costs, delays and exit codes. It records its arguments and working folder for each call.
- Tests that need a fake notifier put fake `osascript` and `notify-send` on `PATH` that record their arguments.
