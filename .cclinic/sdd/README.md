# SDD documentation

cclinic is a Node.js/TypeScript command-line tool that sets up spec-driven development (SDD) for an existing project. It scans the project's own code and documents (skipping dependencies, build output, binaries and secrets), redacts secrets, and uses Claude (Claude CLI by default, or the Anthropic API) to generate overview, stack, architecture, developer-guideline and per-capability spec documents (spec/validation/verification) into .cclinic/sdd/. It also installs agent skills and AGENTS.md/CLAUDE.md workflow sections.

Generated by cclinic from this project's code and documents. Treat these files as the source of truth for what the project must do, and keep them updated as it changes.

## Specs

| Spec | Goal | Area code |
|---|---|---|
| [agent-instructions](specs/agent-instructions/spec.md) | Install marked AGENTS.md and CLAUDE.md sections into a target project so coding agents follow a spec-first lifecycle (open-task check, prompt, spec approval with an optional visual review doc, implementation approval, optional commit), without disturbing the user's own instructions or triggering reprocessing by cclinic. | `INSTR` |
| [agent-skills](specs/agent-skills/spec.md) | Install nine portable agent skills (create-spec, refine-spec, write-code, implement-spec, test-spec, local-env, product-engineer, review-doc, review-code) into .agents/skills and .claude/skills, plus a marked AGENTS.md section, without overwriting other people's or edited work and without affecting analysis. | `SKILL` |
| [cli-commands](specs/cli-commands/spec.md) | Provide the cclinic command-line interface with commands, options, limits, confirmation, output modes, safety checks and exit codes. | `CLI` |
| [code-review](specs/code-review/spec.md) | Review each change against the project's coding guidelines (and Claude Code's built-in review when available) with a `review-code` skill, after QA and before the preview, and fix what it finds, so the user approves and commits reviewed code. | `CREV` |
| [content-extraction](specs/content-extraction/spec.md) | Extract text with positions (line numbers, pages, headings) from code, text, PDF and DOCX files locally. Tolerate per-file failures with warnings, never silently truncate, and split large files into position-preserving chunks. | `EXT` |
| [file-discovery](specs/file-discovery/spec.md) | Find the project's own code and documents on any technology stack, excluding dependencies, build output, binaries and secrets, and record and report every skipped file with a reason. | `DISC` |
| [git-setup](specs/git-setup/spec.md) | Detect Git state (installed, repository, remote) read-only, create a local repository with git init only after user confirmation, alert non-fatally when no remote exists, and use the last 14 days of sanitised commit history as context for combine and spec generation, without ever committing, staging, adding remotes or pushing. | `GIT` |
| [llm-providers](specs/llm-providers/spec.md) | Reach Claude through the Claude CLI (default) or the Anthropic API with the same results and safety rules on both. This covers one-time provider selection, retries, timeouts, budget and cost estimates, prompt-injection and secret safety, usage-limit handling, and central model constants. | `LLM` |
| [local-environment](specs/local-environment/spec.md) | Set up a local environment with the `local-env` skill, and show how to review each change, such as a link or a simulator build. | `ENV` |
| [model-selection](specs/model-selection/spec.md) | Let users choose the Claude model and reasoning level through interactive menus, command-line options, environment variables or a saved default, with built-in defaults (Sonnet, medium) and fully scriptable, non-hanging behaviour. | `MODEL` |
| [quality-tooling](specs/quality-tooling/spec.md) | Enforce architecture, lint, types, coverage, mutation testing and test infrastructure so that every change to cclinic passes one repeatable quality gate (npm run verify) and the test suite is deterministic and runs without real Claude or network. | `QUAL` |
| [spec-analysis](specs/spec-analysis/spec.md) | Group extracted project content into modules, summarise each with an LLM, combine the summaries into project-wide data, and generate traceable specs (requirements, acceptance criteria, test cases) with stable IDs, caching, resumability and validation, while keeping LLM calls to a minimum. | `ANA` |
| [spec-output](specs/spec-output/spec.md) | Validate the generated document set before saving, then write it to .cclinic/sdd (or --out) atomically with overwrite protection for hand-edited or foreign folders, and deterministic Markdown output. | `OUT` |
| [task-tracking](specs/task-tracking/spec.md) | Keep the roadmap (ordered milestones) and planned tasks in a local SQLite database at .cclinic/tasks.db, read and changed with `cclinic tasks` commands that need no Claude, network or extra dependency. | `TASK` |

## The three files in each spec

| File | Question it answers | Written for | ID format |
|---|---|---|---|
| `spec.md` | What must the software do? | Developers and AI coding tools | `FR-<AREA>-NNN` |
| `validation.md` | Does it meet the need? | Product owners and reviewers | `VAL-<AREA>-NNN` |
| `verification.md` | Which test proves each requirement? | Automation testers | `TC-<AREA>-NNN` |

## Requirement status

| Status | Meaning |
|---|---|
| `confirmed` | Code and documents agree |
| `code-only` | Found in code, with no supporting documents |
| `docs-only` | Found in documents only. It may not be built yet |

## Rules

- AI coding tools follow [developer-guidelines.md](developer-guidelines.md) for all code.
- Automation testers write tests from each spec's `verification.md`.
- Don't assume a `docs-only` requirement is implemented.
- Check [open-questions.md](open-questions.md) before relying on a disputed requirement.
- If the project has cclinic's skills (`create-spec`, `refine-spec`, `write-code`, `implement-spec`, `test-spec`, `local-env`, `product-engineer`, `review-doc`, `review-code`), use them for that work.
