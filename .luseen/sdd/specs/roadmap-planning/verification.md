# roadmap-planning: verification

Test cases for automation testers. Start each automated test's name with its `TC` ID.

## Test setup

- Test runner: Vitest, with unit tests colocated in `src/core`, and integration and e2e tests in `test/integration` and `test/e2e`.
- Each test uses a fresh temporary project with `.luseen/sdd` and the luseen skills installed.
- No test calls real Claude or the web. A fake `claude` on `PATH` (extending `test/fixtures/fake-claude/claude`) plays a scripted sequence of turns. For each turn it:
  - records its arguments and the prompt or message it was given;
  - writes the user message, its assistant text and its tool calls to a transcript file under a fake `CLAUDE_CONFIG_DIR`, keyed by `--session-id` or `--resume`, in Claude Code's transcript format;
  - emits matching `stream-json` events;
  - can start the MCP server named in `--mcp-config` and call scripted `plan_suggest` and `plan_propose` inputs through it, recording the tool results;
  - can report usage-limit events, end with no text, or wait for a given time.
- A Claude Code host is simulated by an MCP client test harness. It starts `luseen mcp`, calls the plan tools, answers elicitation with scripted answers or declares no elicitation support, and sends the `session-link` hook input with a session ID and transcript path.
- Interactive terminal tests drive luseen through a pseudo-terminal with scripted messages.
- GUI tests drive the Plan panel in a headless browser against `luseen gui` with the same fake `claude`.
- Attachment fixtures in `test/fixtures/attachments/`: `mock.png` (small), `big.png` (6 MB), `brief.pdf`, `brief.docx` containing the text "Target: clinics" and a fake API key, `notes.md`, `data.csv`, `song.mp3`, and `doc.pdf` of 21 MB, generated in setup when large.
- A valid proposal below means one that passes FR-PLAN-009 (or FR-PLAN-019 in task mode).
