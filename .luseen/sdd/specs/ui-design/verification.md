# ui-design: verification

Test cases for automation testers. Start each automated test's name with its `TC` ID.

## Test setup

- Test runner: Vitest. Skill text tests go in src/core/agent-skills.test.ts, design-file checks in src/core/design.test.ts, the setup step in test/integration/design.test.ts and test/e2e/design.test.ts, plugin files in test/integration/claude-plugin.test.ts.
- luseen's behaviour is tested with test/fixtures/fake-claude/claude, which records its arguments and environment. A new `FAKE_CLAUDE_DESIGN` chooses `valid`, `invalid`, `none` or `fail`, and `FAKE_CLAUDE_ALSO_WRITE` names other files to change.
- Fixtures: test/fixtures/design/valid (a complete design system), and copies with one fault each (a missing section, a token without `$value`, a broken reference, invalid JSON, no style guide).
- What the skill makes an agent do can only be judged with a real agent, so those cases are `manual`. Use a small web app fixture with a few hard-coded colors, repeat each at least 3 times, and judge by the stated result rather than exact wording. Contrast ratios are checked with any WCAG 2.2 contrast calculator.
