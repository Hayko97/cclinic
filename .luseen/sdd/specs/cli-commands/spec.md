# cli-commands

## Goal

Provide the luseen command-line interface with commands, options, limits, confirmation, output modes, safety checks and exit codes.

`luseen environment`, `--environment` and `--no-environment` are specified in [local-environment](../local-environment/spec.md).

## Edge cases

- Folder named like a command is reached with ./ prefix (e.g. luseen ./model).
- Typo such as `docter` or `--dry-rn` exits 2 with a suggestion and runs nothing.
- Path argument that is a file rather than a directory exits 2.
- No TTY and no --yes exits 2 immediately instead of hanging.
- Stale lock file from a dead process is replaced.
- Subscription login hides cost figures; API provider shows an estimate.
- Home folder or filesystem root with --yes still refused without --allow-broad-target.
- A skills installation failure after successful generation is only a warning.
- NO_COLOR set but empty does not disable color in a TTY.
- Second Ctrl+C exits immediately.
- A project with both `.cclinic/` and `.luseen/` keeps both and uses only `.luseen/`.
- A cclinic GUI or auto run still running in the project blocks the folder move, so it never moves files under a live process.
- `.cclinicignore` and `.luseenignore` both exist: neither is renamed, and `.luseenignore` is used.
- Both folders exist and only `.cclinicignore` does: it's renamed, so its rules still apply.
- A project generated with `--out docs/sdd`: its skills and section keep pointing at `docs/sdd` after the move.

## Non-goals

- API keys as CLI options.
- Per-project config or profiles.
- Shell completions.
- Self-update.
- Renaming git branches from earlier auto runs (`cclinic/auto/...`); they stay as they are.
- A `cclinic` binary or npm alias inside the `luseen` package.
- Analytics or telemetry.
