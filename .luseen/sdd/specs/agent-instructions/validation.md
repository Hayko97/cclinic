# agent-instructions: validation

Acceptance criteria from the user's point of view.

| ID | Covers | User need | Accepted when |
|---|---|---|---|
| VAL-INSTR-001 | FR-INSTR-001, FR-INSTR-002, FR-INSTR-003, FR-INSTR-004, FR-INSTR-010 | After setup, a new coding agent session already knows the spec-first workflow without being told. | After running luseen (or its skills command) on a project, a fresh session in Claude Code, Codex, Cursor or Copilot describes the workflow and the right documents folder, and the instructions stay short. |
| VAL-INSTR-002 | FR-INSTR-005, FR-INSTR-006, FR-INSTR-020 | I control when instruction files are added and need no extra account to add them. | Opting out of skills or doing a preview leaves both files untouched; installing works without Claude access; luseen never commits or pushes. |
| VAL-INSTR-003 | FR-INSTR-007, FR-INSTR-008, FR-INSTR-009 | My own instructions in AGENTS.md and CLAUDE.md are never lost or altered. | My text stays exactly as written and is still followed after installing or re-installing; a damaged section leaves that file alone and tells me; repeating the install changes nothing. |
| VAL-INSTR-004 | FR-INSTR-011, FR-INSTR-012, FR-INSTR-013 | Adding or committing the instruction files must not cost me a new analysis run. | Running luseen again after installing and committing the files triggers no reprocessing and changes none of the generated documents. |
| VAL-INSTR-005 | FR-INSTR-014 | Questions get plain answers and code requests are tied to the right spec. | A question is answered with no spec or code changes; for a code request the agent states which spec applies before acting, or asks me if unsure. |
| VAL-INSTR-006 | FR-INSTR-015 | I review and approve the spec before any code is written. | A feature or bug request yields a spec update for me to approve or reject; no production code changes until I approve; rejecting leads to a revised spec. |
| VAL-INSTR-007 | FR-INSTR-016 | After approval I get working code with honest test results and a chance to review. | The agent builds the approved change, reports real test results, asks me to approve or request changes, and does not commit by itself. |
| VAL-INSTR-008 | FR-INSTR-017, FR-INSTR-018 | Small changes are quick and I can override steps, yet the agent never guesses. | A typo or refactor skips spec review; telling the agent to skip a step works and is acknowledged; with no docs the agent asks me to run luseen; with nobody to approve it stops at the spec. |
| VAL-INSTR-009 | FR-INSTR-019 | Commits happen only when I want them and contain exactly the change. | After I approve the implementation the agent asks to commit; if I agree the commit contains this change's spec, code and tests only and nothing is pushed; if I decline nothing is committed. |
| VAL-INSTR-010 | FR-INSTR-001, FR-INSTR-003, FR-INSTR-019, FR-INSTR-020 | Claude Code and other agents share a single source of the rules. | Claude Code follows the same workflow as other agents because CLAUDE.md only points to AGENTS.md. |
| VAL-INSTR-011 | FR-INSTR-021, FR-INSTR-022 | Nothing reaches me for review until it has been tested against its spec, and failures are fixed rather than hidden. | After implementing, the agent reports a QA run of the spec's test cases and acceptance criteria; when one fails, it fixes the code and tests again, or returns to the spec if that's what is wrong; no test is weakened. |
| VAL-INSTR-012 | FR-INSTR-023 | The agent doesn't loop forever on a problem it can't fix. | After 3 failing QA rounds, the agent stops and tells me what still fails, and doesn't ask me to approve. |
| VAL-INSTR-013 | FR-INSTR-024 | I only test by hand something that already passed QA, and I know what to check. | The preview comes after a passing QA run, with steps for each manual test case; when I ask for changes, the next preview comes after another QA run. |
| VAL-INSTR-014 | FR-INSTR-025 | The QA agent tests, rather than starting its own spec review. | A QA run returns test results, and doesn't ask for spec approval or stop at the spec stage. |
| VAL-INSTR-015 | FR-INSTR-026, FR-INSTR-027 | QA and fixing never loop without me. | Wrong tests get fixed to match the spec; however failures alternate, the agent stops after 3 QA runs, and only starts again after I reply. |
| VAL-INSTR-016 | FR-INSTR-028 | Changes with no spec are still tested. | For a refactor no spec covers, I get the result of the full checks and a note that no spec covers it, without being asked to create one. |
| VAL-INSTR-017 | FR-INSTR-029, FR-INSTR-030 | Planned work isn't forgotten, and I stay in control of it. | When I send a prompt while tasks are open, the agent lists them and waits for me to choose: work on one, remove it, or keep it and carry on. It doesn't keep asking once I've said keep. |
| VAL-INSTR-018 | FR-INSTR-031, FR-INSTR-032 | Planning and tracking happen in the normal flow. | Asking to plan gets me pointed to `luseen plan`, where the PM creates the roadmap with me; working on a task marks it in progress, and approving the implementation marks it done. |
| VAL-INSTR-019 | FR-INSTR-033, FR-INSTR-034 | When reviewing a spec, I can ask to see what the change will look like before deciding. | At the end of every spec review I'm offered approve, refine and review-doc. Choosing review-doc gives me a link to a visual doc and asks me to approve or refine the spec; no code is written until I choose approve. |
| VAL-INSTR-020 | FR-INSTR-035 | Review docs don't end up in my commits unless I want them. | After I agree to commit, the commit has no files from `.luseen/reviews/` unless I asked for them. |
| VAL-INSTR-021 | FR-INSTR-036, FR-INSTR-037 | Agents use the checked steps when they're there, and can't approve for me | With the luseen tools available, the agent uses them for every stage, tells me when a step is refused and why, and never answers an approval for me; without them it follows the written steps |
| VAL-INSTR-022 | FR-INSTR-038 | I'm not interrupted while QA and the developer fix bugs. | When QA fails, the developer fixes the bugs and QA runs again without asking me, and I'm asked to approve only after QA passes, or told what still fails after the 3rd run. |
| VAL-INSTR-023 | FR-INSTR-039, FR-INSTR-040, FR-INSTR-041 | Problems found but not fixed now aren't forgotten | After a change, every follow-up from the review, and every failure left when the agent stopped, is in `luseen tasks list` with enough detail to fix it later, once each, and nothing already fixed is there |
| VAL-INSTR-024 | FR-INSTR-042 | I decide which minor issues are worth tracking | The report lists the tasks saved for me, and asks which unfixed nits, disputed findings or other issues to save; only those I pick become tasks, and answering doesn't approve the change |
